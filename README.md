# Вечер покраса у Карповых

Локальный сервис для бронирования мест на вечера покраса. Данные хранятся в Postgres, сайт и API запускаются через Node.js.

## Возможности

- Авторизация через отдельное окно входа/регистрации.
- Первый зарегистрированный пользователь автоматически становится админом.
- Админ может выдавать админ-права другим пользователям.
- Создавать и удалять вечера покраса может только админ.
- Бронирование покрасомест и игровых столов.
- Игровые столы поддерживают двух игроков.
- Схема зала с 16 местами: клик по креслу открывает запись на выбранное место.
- У каждого кресла две строки: 19–21 — первая смена, 21–00 — вторая. В каждой смене независимы участник, время и оплата; форма меняет только выбранное кресло и смену.
- Для гостей запись начинается с регистрации или входа с возвратом к выбранному месту.
- Архив показывает прошедшие вечера списком от новых к старым; каждый день открывается отдельно.
- Участников за покрасочным столом можно перетаскивать мышью или пальцем: на свободное кресло — перенос, на занятое — обмен местами. Админ может перемещать всех, пользователь — только добавленные им записи (при обмене нужны права на обе).
- С клавиатуры: пробел на участнике, Tab до нужного кресла, Enter для переноса; Escape отменяет выбор. В архиве перемещение отключено.
- Перетаскивание переносит запись только между креслами одной смены.
- Отметка оплаты по каждому участнику.

## Запуск

Нужны Docker Desktop и Node.js.

```powershell
cd "C:\Users\Journeymagne\Documents\Трекер посещения покрасавечеров"
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

После запуска сайт будет доступен по адресу:

```text
http://localhost:3000
```

Postgres поднимается через Docker Compose на локальном порту `55432`.

## Файлы

- `server.js` - Node.js сервер, API и инициализация таблиц Postgres.
- `app.js` - клиентская логика сайта.
- `index.html` - разметка страницы и диалогов.
- `styles.css` - темная тема интерфейса.
- `docker-compose.yml` - Postgres для локального запуска.
- `start.ps1` - запуск базы и сайта.

## База данных

Сервис создает таблицы автоматически при старте:

- `users`
- `user_sessions`
- `paint_days`
- `booking_slots`

Если первый пользователь уже был создан до появления админ-ролей, сервер при старте назначит админом самого раннего пользователя, если админов еще нет.

## Продакшен

### Предпросмотр схемы столов

`node scripts/preview.cjs` запускает локальный предпросмотр схемы зала на
`http://127.0.0.1:4318/`. Это пример данных без подключения к базе;
записи в предпросмотре не сохраняются.

`node scripts/check-seating.cjs` проверяет интерфейс в Chrome через Playwright
с имитацией API: регистрацию, сохранение выбранного места, архив и мобильную
верстку. Нужны установленный Chrome и пакет `playwright` (путь к пакету при
необходимости задаётся через `PLAYWRIGHT_MODULE`). Скриншоты сохраняются в
`.superpowers/previews` или в каталог из `PREVIEW_OUTPUT`.

`node scripts/test-move-booking.cjs` проверяет перенос и обмен на настоящей
PostgreSQL, включая сохранность оплаты и контактов, права, конкурирующие
запросы и откат. Нужна отдельная временная база `paint_move_test`; строка
подключения задаётся через `MOVE_TEST_DATABASE_URL`. Тест создаёт и удаляет
только собственную временную схему.

`node scripts/test-shifts.cjs` использует ту же временную базу и проверяет
через HTTP миграцию старых записей, независимость двух смен, оплату, удаление,
совместимость старых клиентов и сохранность данных после перезапуска.

При первом запуске новой версии старые записи сохраняются в первой смене
(`shift_index = 0`), вторая остаётся свободной. Миграция выполняется атомарно
и повторно безопасна: добавляет колонку смены и заменяет уникальность места
на уникальность места в смене. Старую версию приложения после миграции нельзя
запускать без адаптации её записи к новой схеме; для отката нужна копия базы
до обновления. В интерфейсе смены обозначены интервалами 19:00–21:00 и 21:00–00:00; время прихода участника указывается отдельно.

### Развёртывание

Деплой на сервер выполняется через Docker Compose (`docker-compose.prod.yml`)
с Caddy в роли реверс-прокси и авто-HTTPS, обновления — автоматически через
GitHub Actions при пуше в `main`. Разовая настройка сервера, DNS и секретов
описана в [`docs/deploy-runbook.md`](docs/deploy-runbook.md).
